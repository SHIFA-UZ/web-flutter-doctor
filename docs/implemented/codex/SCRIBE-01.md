**Answers (round 1, all fixed; the background one checked on the emulator, so no second round):**
1. *Recording stops in the background:* fixed on Android; the recorder starts a foreground service of type microphone (`utils/RecordingService`, its notification "Recording the consultation", FOREGROUND_SERVICE(_MICROPHONE) in the manifest) and stops it with the recording; dictation gets it too. Checked: home pressed while recording, the service runs in the foreground with type microphone, back in the app the timer went on and Process uploaded; the service stopped. iOS keeps recording with its `audio` background mode (Info.plist), not run yet. Rotation doesn't recreate the activity (`configChanges`).
2. *Overlapping uploads:* fixed; an upload marks the visit "uploading" (reset in `finally`), Start is replaced by the (busy) retry button meanwhile, and Retry does nothing while one is on its way.
3. *Hidden recorder state:* fixed; the screen wrapper owns the scribe's recorder, permission and plan check; the content gets its state (`scribe: DictationState?`, `scribeAllowed`) and callbacks (start, cancel, finish, retry, dismiss), so previews show it (the workspace screenshot now has the recording).
