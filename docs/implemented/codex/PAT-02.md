**Answers (round 1):**
1. *Spring pages rejected (P1):* fixed; the directory (like the booking list) reads a plain list or a Spring page (`content`, `last`; a short list is the last page). Tested with a page answer.
2. *A late refresh restores patients after sign-out (P1):* fixed; reads are numbered and `clear()` moves the number on, so an answer started before sign-out is dropped.
3. *A refresh overwrites creates and updates (P1):* fixed; `create` / `update` move the number on too, so a read that started earlier can't replace the list (or reset the TTL). Tested with a held read across a create.
4. *Stops at 2,000:* the cap is now 200 pages of 100 (20,000), and reaching it is logged.
5. *Empty prophylaxis body:* already "no setting": `apiCall` gives null for an empty body (tested: the first assertion of the prophylaxis test runs with an empty body). Kept, and an explicit JSON `null` or `{}` reads the same.
6. *Prophylaxis decoding outside the Result:* fixed; decoding runs in `mapCatching`, so a bad object is a failure, and an unexpected shape (array, primitive) is a failure instead of null.
