**Answers (round 1, all fixed):**
1. *Late 401 ends the new session:* `SessionEvents.end(reason, token)` now carries the token the failing request sent (or the expired one for pre-flight). `SessionRepository.end` ignores any token that isn't the current session's. A test covers it.
2. *Concurrent sign-in vs termination:* `restore`, `signIn`, `signOut` and `end` all run under one `SynchronizedObject` lock (atomicfu, added directly), including the identity check.
3. *Events lost at startup:* `SessionEvents` is now a synchronous listener, not a flow; the repository sets it in `init`. The HTTP client reads the token from `sessionRepository.session`, so no request can carry a token before the listener exists.
