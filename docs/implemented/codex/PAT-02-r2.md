**Answers (round 2, all fixed):**
1. *Previous-session answers contaminate the next session (P1):* `create` / `update` apply only within the session they started in (a sign-out moves it on), and a single `patient()` read applies only if nothing newer happened since it started, so it can't overwrite a later update.
2. *Truncated directory returned as complete:* reaching the page cap is now a failure; the cached list stays and the caller sees the error.
3. *Prophylaxis decoding untyped:* decoded by `apiCall<ProphylaxisSetting?>` itself: empty answer → null ("no setting"), unreadable → its typed, logged failure.
4. *Invalid directory payloads erase the list:* an answer that is neither a list nor a page with `content` is a failure, and the list stays. Tested.
