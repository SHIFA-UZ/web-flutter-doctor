**Answers (round 1, all fixed):**
1. *Staff registration re-keying an existing account:* only reachable when the invitation has no address (C-4), since the backend refuses any other address otherwise. In that case the app now asks `check-existing-patient` first (it matches any existing user by e-mail, case-insensitively) and refuses an address with an account ("…Ask the clinic to send the invitation to that address."), failing closed on any error. The server-side fix stays BE-29 (extended to `register-clinic-staff`). Tested.
2. *No usable token after creation:* `TokenResponse.token` reads a missing token as ""; when `register` / `register-clinic-staff` succeeded but the token can't start a session, the screen shows `registrationIncomplete`, clears the passwords, disables the submit button and Back goes straight to Sign In (no discard question). Applies to the doctor's registration too. Tested.
Item 1 is a security path, so a second round follows.
