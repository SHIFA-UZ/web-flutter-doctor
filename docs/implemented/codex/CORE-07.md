**Answers (round 1, all fixed). They were in the code copied from the patient app; the patient app still has them (follow-up for that repo):**
1. *URLs in logs:* the player logs only `what/extra` codes or the exception class; the recorder logs the exception class.
2. *Failed init keeps the player:* the `MediaPlayer` is assigned before `setDataSource`/`prepareAsync`, so `release()` frees it.
3. *Pause while preparing:* `prepared` is tracked separately. A toggle while preparing only changes the requested state, and `onPrepared` starts only if playing is still wanted; `tick()` waits for prepared. Checked on the emulator: play then pause during preparation stays at 0 s / 3 s, and resuming plays to 2 s / 3 s.
4. *iOS shows the previous PDF:* `UIKitView.update` sets `document`.
5. *PDF opens on the UI thread:* `produceState` on `Dispatchers.IO`, with a Loading box meanwhile; `close()` runs on a background thread.
6. *PDF failure cleanup:* the temp file is deleted in `finally`, and the descriptor is closed when `PdfRenderer` fails.
7. *Auto-run timer:* the 3 s starts from `recording = true`, i.e. after permission and a successful `start()`. Re-run on the simulator: record, then playback 0 → 2 s / 3 s.
