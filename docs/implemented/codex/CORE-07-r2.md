**Answers (round 2):**
1. *Closed renderer observable:* fixed. The document state is `remember(bytes)`, a new state per document, so a closed renderer is never read again; in-flight page renders of the old one fail inside their `runCatching`.
2. *Cancellation while opening:* fixed. An `Owner` (atomicfu lock) receives the renderer inside the IO block. Whichever of the opening thread and the disposal comes second closes it, so nothing leaks however cancellation lands.
3. *Recording again resumes the old file:* fixed. The player is released before every new recording. Checked on the emulator: a second recording plays with its own duration (21 s, not the first one's 2 s).
4. *Stateless content split:* not applied. `SpikesScreen` is the debug-only harness CORE-07 calls throwaway; it never ships in a release build, has no ViewModel-worthy state, and isn't a product screen. Product screens follow the `XxxScreenContent` rule.
